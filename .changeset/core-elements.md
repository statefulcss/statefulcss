`analyze(root, settings)` reads a stylesheet into the Stateful CSS model, for the parts model. A component is a top-level block for a class or for `[data-component="name"]`, with its `@scope (root) to ([data-component])` and its doc comment; its elements are its root, its parts (`data-part`), its slots (`data-slot`), pseudo-elements and content. No class is ever a part, a class in the utilities layer is a utility, and a selector with no class and no component attribute is a global element, with theme scopes and `[data-color-scheme]` selectors marked. Every block has its resolved selector, its element, the path from the component root, its conditions and its kind: the element's own block, a variant, a state with its groups (context, interaction, semantic, blocking), or `@supports`. The guard around interaction states is read with the blocking states it lists, `:has()` with the part it names, and `@container style()` with the variable it asks about. Every declaration has its role (token, component variable, state variable, part variable, private, query variable, or a library variable the doc comment names), and every variable has its writes, its default, the part it's named for, the reads that reach it and whether a variant or a state changes it. Every place a selector names a part says where it is: inside the component's scope, on a placement path into a slot, inside `:has()` on the root, or outside. The model is plain, read-only data that points by id, so it's JSON once its PostCSS nodes are dropped. Syntax core can't read is recorded in `unknowns` with the elements it sits in, never thrown on; a declaration whose value can't be read is kept and marked. Works the same on plain CSS, SCSS and Vue files. `roleOf`, `rolePrefixes`, `readsOf`, `namedFor`, `longhandsOf` and `overlaps` are exported for tools.
