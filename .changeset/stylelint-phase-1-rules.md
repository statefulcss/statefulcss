The first Stateful CSS rules, read from `@statefulcss/core`'s model with the project's `statefulcss.config` settings, in plain CSS, SCSS and the `<style>` blocks of a `.vue` file: `variable-role-prefix`, `theme-tokens`, `bind-once`, `bind-through-state-variables`, `blocking-states-win` (fixable), `visited-colors-only`, `no-undeclared-state-variables`, `parts-in-scope`, `part-variables` and `no-abbreviations`. `config-check` checks the Stylelint config itself, once for each run (a `stylelint` command, a `stylelint.lint()` call, so each file an editor lints): `bind-once` without `bind-through-state-variables`, `bind-once` and `declaration-block-no-duplicate-custom-properties` both off, and `no-descending-specificity` on. `recommended` and `compatible` switch every rule on at its level, set `declaration-block-no-duplicate-properties` to a warning that suggests `@supports` and never deletes a fallback, and switch `declaration-block-no-duplicate-custom-properties` off. `recommended` also accepts what Sass, Vue and CSS Modules add to CSS, by file name. A settings file that can't be used, or a setting written as a rule option, is an invalid option. A rule that fails on a file gives one warning on it, with a link to report the problem. Each rule's README ships in the package, and `ruleMeta` gives its URL on GitHub and whether the rule can fix.
